A selection sort repeatedly finds the smallest item left in the unsorted part of the list and swaps it into place at the front. It is not on the OCR specification, but it is a natural algorithm to compare with bubble and insertion sort: it makes far fewer swaps, but just as many comparisons.

How it works

  1. Set minIndex to the position of the first unsorted item.
  2. Scan the rest of the unsorted part. Whenever an item smaller than the one at minIndex is found, minIndex is updated to point at it.
  3. When the scan reaches the end, the item at minIndex is the smallest left in the list.
  4. Swap it with the first unsorted item, unless it is already there.
  5. The sorted part is now one item longer. Repeat from the next position.
  6. After n − 1 passes every item is in its final place.
  • It works in place, needing only a few extra variables.
  • Each pass makes exactly one swap at most, so a selection sort never does more than n − 1 swaps in total — far fewer than a bubble sort, which can do up to about n² ÷ 2.
  • It always scans the whole unsorted part on every pass, even if the list is already sorted, so it has no best case speed-up the way bubble and insertion sort do.
  • It is not stable: swapping the smallest item into place can jump it past an equal item, changing their original order.
