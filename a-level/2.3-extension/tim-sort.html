Tim sort is a hybrid sort: it combines insertion sort and merge sort to get the best of both. It splits the list into small runs, sorts each run with insertion sort, then merges the runs back together exactly like a merge sort. It is the sort used by Python's sort() and by Java for sorting objects. This page shows a simplified version of the real algorithm.

How it works

  1. Choose a small run length, minRun (this demo uses 4).
  2. Starting from the front of the list, find the next natural run: a stretch of items that is already in non-decreasing order.
  3. If that natural run is shorter than minRun, extend it up to minRun items and sort the whole run with insertion sort, just as on the Insertion Sort page.
  4. Record the run's start and end, and move on to find the next run, until the whole list has been split into runs.
  5. Repeatedly merge neighbouring runs in pairs, exactly as in Merge Sort, until only one run — the whole sorted list — is left.
  • Insertion sort is very fast on short or nearly-sorted runs, so it is used to get each small run in order cheaply.
  • Merging is then used to combine those runs, giving the same O(n log n) guarantee as a merge sort — without insertion sort's O(n²) risk on a long list.
  • If the whole list is already sorted, it is found to be one single natural run, so no merging is needed at all: this is where tim sort's excellent best case comes from.
  • Real tim sort goes further than this demo: it picks minRun based on n (usually between 32 and 64), reverses strictly descending runs instead of insertion-sorting them, and merges runs using a smarter stack and a "galloping" mode that speeds up merges when one run is consistently winning.
