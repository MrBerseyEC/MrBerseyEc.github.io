Abstraction means removing unnecessary detail from a problem so that only the features needed to solve it are left. The result is a simplified representation of reality. Every computer model, map, simulation and data structure is an abstraction of something.

From a city to a map

Drag the slider to strip detail away from this city, one layer at a time, until only a metro map is left. The table shows which questions each version can still answer.

The metro map is the better tool for planning a journey because so much has been left out. It is also wrong about distance, direction and the shape of every line. An abstraction is judged by whether it keeps what matters for its purpose, not by how closely it matches reality.

How an abstraction differs from reality

A game needs a ball that bounces. The dashed line is how a real ball moves. Choose which properties of the ball your model includes, then drop it. The more you simplify, the less the model behaves like the real thing.

Why programmers rely on abstraction

In programming, abstraction separates what a program does from how it does it. Each generation of programming language hid more of the machine, so that the programmer could concentrate on the problem. Here is the statement x = a + 5 at all three levels. Step through it to see what the processor really does.

1st generationMachine code


      
  • The binary patterns the processor executes
  • Every opcode and memory address written by hand
  • Slow to write, and errors are hard to find

    
2nd generationAssembly language

      
  • A mnemonic in place of each opcode
  • The programmer still manages the accumulator and memory
  • Must be rewritten for a different processor

    
3rd generation, from the 1960sHigh-level language

      
  • Reads like the problem being solved
  • No need to know where x and a are stored
  • Runs on any computer with a translator

  

  

    

    

  

  






  
Data abstraction: a queue

  
A queue is an abstract data type. The programmer who uses it only needs to know its operations: items join at the rear and leave from the front. How the items are stored is hidden. Use the queue first, then reveal what is going on underneath.

Abstraction by generalisation

  
The people of Königsberg wanted a Sunday walk that crossed each of the city's seven bridges exactly once. Click a piece of land to start, then click bridges to cross them. Then switch to the graph that Euler drew in 1736: each piece of land became a node and each bridge an edge.

  

    

    
    
  

  

    
    

      

      

      

    

  

  
Summary: kinds of abstraction
  

    
KindWhat it meansExample

    
Representational abstractionA representation arrived at by removing unnecessary detailsA metro map, a flight simulator, a model of a housing estate

    
Abstraction by generalisationGrouping by common characteristics, giving an "is a kind of" relationshipKönigsberg is a kind of graph problem. Dog and Cat are kinds of Animal, so what they share is written once in the superclass

    
Procedural abstractionUsing a procedure while knowing only what it does and how to call itdrawTriangle("red", 4.5, 2.0)

    
Data abstractionHiding how data is represented, so only its operations are seenIntegers and reals; a queue with enqueue and dequeue
