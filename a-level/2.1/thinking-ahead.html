Thinking ahead means working out, before any code is written, what a solution will need: the data that goes in, the results that come out, the conditions that must already be true, and anything that could be reused or kept ready in advance.

Inputs and outputs

At its most abstract, every computational problem looks the same. The inputs are the information the problem needs, and the outputs are its solution. Stating exactly what they are is the first step towards solving it. A subroutine has inputs and outputs too: its parameters and the value it returns.

Input → Computational problem → Output

The same skill is needed however the problem is presented. Classify each item as an input, an output or neither.

Preconditions

  
A precondition is something that must be true before a subroutine is called, if it is to work correctly. Choose a function, then try calling it. Why state preconditions?

  
    
    
  • Anyone calling the subroutine knows exactly which checks they must carry out first.
    • 
    
  • If there are no preconditions, the caller can be confident that the subroutine does the checking itself, so the same checks are not coded twice. A shorter program is easier to debug and maintain.
    • 
    
  • A subroutine with clearly documented inputs, outputs and preconditions is reusable. It can be put in a library and called from any program.
    • 
    
  • A precondition can make a better solution possible. If a list is known to be sorted, it can be searched with a binary search.
    • 
  






  
Caching

  
Caching is the temporary storage of data or instructions that have been used once and may be needed again soon. Fetching a web page from the server takes 300 ms here, and reading it from the cache takes 5 ms. Click pages to request them.

Benefits
    
      
  • Much faster access to data that is used repeatedly
    • 
      
  • Saves bandwidth, because pages and images are not downloaded again
    • 
      
  • Reduces the load on the server or the slower storage device
    • 
      
  • The same idea is used throughout a computer: cache memory in the CPU, the disk cache and the browser cache
    • 
    

    
Drawbacks
    
      
  • The cached copy can be out of date (stale) if the original has changed
    • 
      
  • The cache takes up memory or storage, and it is limited in size
    • 
      
  • Deciding what to keep and what to remove is complicated to get right
    • 
      
  • If the wrong data is cached, nothing is gained and the space is wasted
    • 
    

  






  
Reusable program components

  
A well-designed component can be written once and used many times: a function or procedure, a class, or a module or library of them. Every time you call print, generate a random number or find a square root, you are reusing code somebody else wrote. A Windows DLL (dynamic link library) is a package of reusable components shared by many programs. Thinking ahead means spotting which parts of a solution could be reused, and designing them so that they can be.
