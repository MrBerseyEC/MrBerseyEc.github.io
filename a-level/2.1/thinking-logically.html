Thinking logically means identifying the points in an algorithm where a decision has to be made, working out the exact condition that controls each one, and understanding how those decisions change the route taken through the program. Most logic errors are found at decision points.

Where are the decisions?

A structured program is built from only three constructs: sequence, selection and iteration. Decisions are made in selection (if and switch) and in iteration (the condition that decides whether a loop goes round again). This algorithm has 3 decision points. A for loop hides a decision too: each time round, the computer tests whether the counter has passed its final value. In a flowchart every decision is drawn as a diamond with two ways out.

Paths and testing

  
To be confident that a program works, every path through it should be followed at least once during testing. The number of paths grows very quickly as decisions are added.

What this means for testing

      
    
        
  • Each decision doubles the number of paths if it is independent of the others, so a few decisions give a lot of test cases.
    • 
        
  • A loop adds a path for every possible number of times it could repeat, including zero times.
    • 
        
  • Test data should be chosen so that every branch of every decision is taken, with values on and either side of each boundary.
    • 
        
  • A path that has never been tested may hide an error, as path 2 did above.
    • 
        
  • Fewer and simpler decisions make a program easier to test. A trace table lets you follow one path by hand.
