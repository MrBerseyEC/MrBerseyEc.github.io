Abstraction means hiding or removing the details you do not need, so you can concentrate on the things that matter. Every game you make in MakeCode Arcade is an abstraction: a real duck becomes a tiny picture and a few numbers, and one block can stand in for dozens of instructions that you never have to think about.

From a real thing to a sprite

Drag the slider to strip detail away, one step at a time, until only what the game needs is left. The table shows which facts survive each step.

The game is better because so much is missing. A game that tracked every feather would be impossible to build and far too slow to play. All a sprite needs is a picture, a position, a speed and a kind.

Keep it or remove it?

Choose a game. For each detail of the real thing, decide whether the game needs to keep it, or whether it can be removed.

One block hides lots of work

The move mySprite with buttons block is an abstraction. You say what you want, and it hides how it is done. Step down through the layers to see what it hides. The duck on the right works the same way in every layer, so try it out each time.


      

        
About 30 times every second, the console:

        
    
          
  1. checks the electrical signal from each of the four arrow buttons
    2. 
          
  2. works out a new speed for every sprite that moves with the buttons
    3. 
          
  3. moves every sprite by its speed, and keeps it inside the screen
    4. 
          
  4. checks every pair of sprites to see if they are touching
    5. 
          
  5. colours in all 19,200 dots on the screen with the background
    6. 
          
  6. copies the 256 dots of every sprite's picture into the right place
    7. 
          
  7. sends all 19,200 colours to the screen
    8. 
        

        

      

    

    

      

      

      

    

  

  
Every layer does the same job. Each layer up hides more detail, so you have less to think about. That is why you can write a game in an afternoon without knowing anything about electrical signals or screen dots.

What the game really knows

  
To you, this is a duck running away from a ghost to grab strawberries. To the computer, each sprite is a picture with a box around it and a few numbers. Play the game and watch the numbers change. Then switch to What the computer sees.

  

    

      

      

      

    

    

      

      

      
The game has no idea that a ghost is scary or that a strawberry is tasty. It only knows each sprite's kind: Player, Enemy or Food. You tell it what should happen when kinds meet, and it checks whether the boxes overlap.

    

  






  
Kinds: one rule for lots of sprites

  
Grouping things by what they have in common is another kind of abstraction. Instead of thinking about strawberry 1, strawberry 2 and strawberry 3, you think about Food. Drag the slider to add more strawberries and compare the two programs.

With kinds

    

  

  
With kinds, the rule is written once. It works for 3 strawberries or 300, and it still works for a strawberry that appears halfway through the game.






  
Make your own block

  
This program makes three ghosts, but it does it by repeating the same three blocks three times. A function lets you wrap those blocks up, give them a name, and then forget how they work. Task: make a function called spawnEnemy that contains the three ghost blocks, then replace each group of three with call spawnEnemy. Type the name into the function block.

  

  

  

  
Once spawnEnemy exists, it is your own abstraction. To add a fourth ghost you add one block, not three. To make every ghost faster you change one number, not three.
