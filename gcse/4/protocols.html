A protocol is a set of rules that governs how devices communicate. Devices made by different manufacturers, running different software, can exchange data because they all follow the same agreed rules about how it is formatted, addressed, sent and checked. The demos below are sorted by the layer of the TCP/IP stack each protocol works at, from the top (what the user's software does) down to the bottom (the cable or radio signal).

The sender turns each character into 8 bits. The receiver gets nothing but a stream of 1s and 0s. Whether it makes sense of them depends on whether it follows the same rules as the sender.

Application layerThe protocols the user's software talks to: browsers, email apps, file transfer

HTTP and HTTPS

The browser sends a request and the web server sends a response. Step through the messages, then see what someone intercepting them on a café's public Wi-Fi can read.

What the person at the next table captures

HTTPS encrypts everything sent between the browser and the web server. It should always be used when personal or financial data is involved, and most websites now use it for everything.

FTP

FTP is used to move files between a client and a server, such as uploading a website's files to the web server. The user has to log in, and can then upload or download files. Choose a direction and step through.

Designer's computer

Web server

FTP is for transferring files, so it can upload as well as download, and it needs a login. HTTP is for requesting web pages and is mainly used to download them. Plain FTP sends the password as text, so secure versions exist, in the same way that HTTPS is the secure version of HTTP.

With IMAP the email stays on the server and each device shows a synchronised view of it, so IMAP suits someone who uses several devices. POP3 downloads the messages and normally removes them from the server, which frees up space there and lets you read them offline, but only on that one device.

DNS Stretch

People use names such as www.example.org, but packets are routed using IP addresses. The Domain Name System turns the name into the address. Choose a website and whether the browser has looked it up before.

DNS is the internet's phone book. Without it you would have to remember the IP address of every website. Devices remember recent answers (a cache), so they do not need to ask again every time.

DHCP Stretch

Every device on a network needs an IP address. The Dynamic Host Configuration Protocol hands them out automatically when a device joins, so nobody has to type them in. Step through a new laptop joining the Wi-Fi.

The laptop's network settings

Why not set them by hand?

Two devices given the same address would clash, and every visitor's phone would need setting up. DHCP keeps track of which addresses are in use and gives each device one that is free. The address is leased for a period of time, then handed back so it can be reused.

Transport layerBreaks the data up and manages getting it to the other end

TCP

TCP splits the message into numbered packets, the packets may take different routes and arrive in any order, and TCP at the other end puts them back together. If any are missing, it asks for them again. Choose how many packets to lose and send.

TCP is reliable: the data that arrives is complete, correct and in order, even though the network underneath gives no guarantees. The cost is some extra waiting while missing packets are sent again.

UDP, compared with TCP Stretch

UDP also sends data in packets but does not number them, check them or resend anything. It has less to do, so it is faster, but lost packets stay lost. The same 12 packets are sent both ways, with the same ones lost.

Internet layerAddresses each packet and routes it from network to network

IP

IP puts the source and destination IP addresses on every packet in a header. Each router reads the destination address and forwards the packet one hop closer. Step through the journey.

An IP address identifies a device on a network, like the address on a house. IP does not check that the packet arrives or put packets in order: that is TCP's job. Together they are called TCP/IP.

Link layerSends the signals over the cable or the air to the next device

Ethernet and Wi-Fi

Ethernet is the protocol for wired LANs and Wi-Fi is the protocol for wireless LANs. Both do the same job, delivering data to the next device, but over different media. Change the conditions and compare.
