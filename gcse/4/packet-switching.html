Data is not sent across the internet in one piece. It is broken up into small packets. Each packet is labelled with the address it is going to and travels there independently, passed from router to router. When all the packets have arrived, they are put back together in the right order. This is called packet switching.

Inside a packet

The data being carried is the body of the packet. A header is attached to the front with the information needed to deliver it and to put the message back together.

The checksum is a number calculated from the data before it is sent. The receiving computer does the same calculation on the data that arrives. If the two results do not match, the packet was damaged on the way, and the destination asks for it to be sent again. In this demo the checksum is the character codes of the data added together, keeping only the last 8 bits.

What happens, step by step

  1. Computer A splits the data into packets, following an agreed set of protocols.
  2. A header is attached to each packet: the source and destination IP addresses, the sequence number, the total number of packets and a checksum.
  3. A router on computer A's network forwards the packets to the ISP.
  4. Each router that receives a packet inspects the header to find the destination address, and uses its routing table to decide where to send the packet next. A packet is usually forwarded several times.
  5. Routers keep each other informed about traffic. If one route is congested, the next packet is sent a different way.
  6. Packets from the same message can therefore take different routes, and may arrive out of sequence.
  7. Computer B checks each packet's checksum and asks for any damaged packet to be resent.
  8. Once every packet has arrived, computer B uses the sequence numbers to reassemble them in the correct order.
