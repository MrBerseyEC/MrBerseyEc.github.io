Two things decide how fast a network feels. Bandwidth is its capacity: the maximum amount of data that can be transferred each second. Latency, also called lag, is the delay between data being sent and it arriving, measured in milliseconds. Sometimes one matters more, sometimes the other.

High latency ruins anything that happens in real time. In an online game, what you see is already out of date and your moves reach the server late. For downloading a large file it hardly matters how long any one byte takes: what counts is the total time, and that depends on the bandwidth.

Units of network speed

The data transfer rate is the speed at which data is transmitted from one device to another. It is measured in bits per second.

UnitAbbreviationBits per second
bits per secondbps1
kilobits per secondKbps1,000
megabits per secondMbps1,000,000
gigabits per secondGbps1,000,000,000

Two things to watch. Network speeds go up in steps of 1000, but file sizes (KiB, MiB, GiB) go up in steps of 1024. And speeds are in bits, while file sizes are usually in bytes, so a file size has to be multiplied by 8.

How long will it take?

Time = file size in bits ÷ transmission speed in bits per second. Get both into bits first.

The answer is only theoretical. Real transmission speeds are not constant, and other things such as latency and how busy the network is affect how long a transfer takes.

Three versions of the same relationship

time = size ÷ speedHow long will a 22 GiB video take at 54 Mbps?
(22 × 1024 × 1024 × 1024 × 8) ÷ (54 × 1000 × 1000) seconds
size = speed × timeA file takes 35 seconds at 40 Mbps. How big is it in mebibytes?
(40 × 1000 × 1000 × 35) ÷ (8 × 1024 × 1024) MiB
speed = size ÷ timeA 6 MiB file takes 4 seconds. What is the speed in Mbps?
(6 × 1024 × 1024 × 8) ÷ (4 × 1000 × 1000) Mbps
