Utility software

Utility software helps to maintain, protect and tidy up a computer system. It is not the operating system and it is not an application for the user's own tasks: it looks after the computer itself.

On a hard disk, a file is stored in blocks. Over time, as files are deleted and new ones saved into the gaps, files get split into scattered pieces (fragmented). The read/write head then has to jump around to read one file, which is slow. Defragmentation moves the pieces so each file is in one continuous run, and gathers the free space together.

Solid state drives should not be defragmented. Any block can be read equally quickly, so there is no speed gain, and the extra writes wear out the flash cells.

Compression makes files smaller, so they use less storage and transfer faster. Paint the 16 × 12 image (4 colours, so 2 bits per pixel) and compare the two kinds.

Original

Lossless: run-length encoding

Each row is stored as runs of (count, colour). Each run costs 6 bits. Decompressing gives back exactly the same image.

Lossy: reduce resolution

Every 2 × 2 square is replaced by its most common colour. Detail is thrown away for good, like JPEG or MP3 do with detail you are unlikely to notice.

A backup is a copy of files kept somewhere else, so they can be restored if the originals are lost through hardware failure, accidental deletion, theft or malware. Backup utilities copy files automatically on a schedule. Pick a method, then press Disaster.

Keep at least one backup off-site or in the cloud: a fire or flood that destroys the computer would also destroy a backup drive sitting next to it.

Anti-malware software scans files and compares them against a database of signatures: patterns of bytes known to belong to malware. Matches are quarantined (isolated so they can't run) or deleted. Heuristic analysis also looks for suspicious behaviour, to catch new malware with no signature yet.

Signature database

Files can be corrupted by a power cut while saving, a failing disk, or a crash. A file repair utility checks the file's structure (here, a checksum for each block) to find damage, and rebuilds what it can from recovery information saved with the file.

The checksum here is the sum of the character codes mod 256. The recovery block is every block XORed together, so XORing it with the good blocks rebuilds one missing block. With two damaged blocks there isn't enough information, which is why repair doesn't always work.
